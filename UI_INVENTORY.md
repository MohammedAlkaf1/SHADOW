# Shadow App — UI Inventory

Read-only visual/structural inventory of the Flutter app at `D:\Shadow\app`, for a Figma redesign brief. Generated by reading every screen's source file(s), resolving `.tr()` keys against `assets/translations/ar.json` / `en.json`, and capturing real screenshots from a connected Android device (portrait, 1080x2400) running the already-installed debug build (package `sa.isleaders.shadow`, logged in as `student@demo.shadow.sa`). The companion platform (`PLATFORM_BASE_URL` in `env.json`, an ngrok tunnel) was reachable during capture, so most screens show real backend data (real course/session/exam data), not placeholders.

No code was modified. All screenshots live in `D:\Shadow\app\scratch_shots\`.

## 1. Splash / Session-Restore Screen

**File:** `lib/pages/splash_screen/splash_screen_widget.dart`

**Literal text (hardcoded, not `.tr()` — this screen has no translation keys at all):**
- `شادو` (app name, large)
- `Shadow` (Latin wordmark, letter-spaced)
- `مرافقك الأكاديمي الذكي` ("Your smart academic companion")

**Structure (top to bottom, centered column):**
- App icon (`assets/icon/app_icon.png`, 100×100)
- 14px gap
- "شادو" — 44px, weight 900, `AppColors.onNavy`, letter-spacing 1.0
- 4px gap
- "Shadow" — 20px, weight 600, `AppColors.terracotta`, letter-spacing 3.0
- 14px gap
- "مرافقك الأكاديمي الذكي" — 17px, weight 500, `AppColors.mutedOnNavy`

**Colors:** `Scaffold.backgroundColor = AppColors.navy` (only screen with a navy full-page background — every other screen uses `AppColors.cream`). Text colors: `onNavy`, `terracotta`, `mutedOnNavy`. No AppSpacing constants used for layout (raw `SizedBox` values: 100, 14.0, 4.0, 14.0) — the only screen using bespoke pixel gaps instead of `AppSpacing.*` tokens.

**States:** Single visual state. Logic behind the scenes: waits `max(2s, session-restore time)`, calls `PlatformClient.tryRestoreSession()`; on success hydrates the student profile then routes to Welcome Selection; on failure routes to Login. No loading spinner, no error state shown — failures are silent and just fall through to Login.

**Navigation:** Entry point (route `/`, app launch only). Leads to → Login (`/login`) or → Welcome Selection (`/welcomeSelection`), never both, no back-navigation possible.

**Screenshot:** `scratch_shots/00_launch.png` — captured.

## 2. Login Screen

**File:** `lib/pages/login/login_widget.dart`

Not a FlutterFlow-generated page (no `_model.dart`) — a hand-written `StatefulWidget`. **All visible strings are hardcoded Arabic literals, not `.tr()` calls** — this screen does not participate in the app's EN/AR localization system at all (confirmed: no `easy_localization` import, no `.tr()` in the file).

**Literal text (verbatim from source):**
- `تسجيل الدخول` (title)
- `سجّل الدخول بحساب منصة شادو الخاص بك` (subtitle)
- `البريد الإلكتروني` (email field label)
- `كلمة المرور` (password field label)
- `تذكرني` (remember-me checkbox label, appears twice in the row — once as the `a11yButton` semantic label, once as visible `Text`)
- `دخول` (submit button, default state)
- `الرجاء إدخال البريد الإلكتروني وكلمة المرور` (client-side empty-field validation error)
- Server error message surfaces directly via `loginResult.errorMessage` (not a fixed string)

**Structure (top to bottom, centered, RTL via explicit `Directionality`):**
- App icon (72×72, centered)
- Title "تسجيل الدخول"
- Subtitle
- Email field (label above input)
- Password field (label above input, obscured)
- "تذكرني" checkbox row (terracotta checkbox)
- [conditional] error text in terracotta
- Submit button (full-width-ish, pill radius, terracotta bg) — shows a white `CircularProgressIndicator` in place of the label while `_loading`

**Colors:** `Scaffold.backgroundColor = AppColors.cream`. Fields: `fillColor: AppColors.surface`, border `AppColors.border` / focus border `AppColors.terracotta`, both at **12.0 radius** — the login screen's own local text-field radius, distinct from `AppSpacing.cardRadius` (20) used almost everywhere else. Submit button uses `BorderRadius.circular(AppSpacing.pill)` (999, fully round) — the only full-pill primary CTA button in the app (every other screen's primary CTA uses 14–20px radius rectangles). Checkbox `activeColor: AppColors.terracotta`.

**States:**
1. **Default** — empty or prefilled fields (prefilled automatically if "تذكرني" was previously checked, from `AppPrefs.getSavedCredentials()`).
2. **Loading** — `_loading = true`, submit button shows a spinner, disabled.
3. **Error** — `_error` non-null, shown as centered terracotta text above the submit button; can be either the local empty-field validation message or the server's real error message.
4. **Prefilled** (real state observed) — email/password auto-populated with saved demo credentials, "تذكرني" pre-checked. Confirmed live: `scratch_shots/20_login_screen.png` shows `student@demo.shadow.sa` and a masked password already filled in.

**Navigation:** Reached from → Splash (session-restore failed) or → Settings (explicit sign-out). Leads to → Welcome Selection on successful login (`context.go(WelcomeSelectionWidget.routePath)`, replacing the stack — no back button on this screen at all, by design or omission; there is no back/close affordance in the UI).

**Screenshot:** `scratch_shots/20_login_screen.png` (prefilled state, captured live after a real sign-out). Loading/error states not captured (would require a live failed submit or artificially throttling the request) — documented from source only.

- **2-card row** (visual + physical modes, each conditionally rendered): equal-width `IntrinsicHeight` row, each card = icon + title (1 line, ellipsis) + description (2 lines, ellipsis), `AppColors.surface` bg, `EchoColors.shadow`
- **Full-width card** (learning mode, conditional): icon tile (40×40, `EchoColors.iconTile`/`iconGlyph`) + title + 2-line description, horizontal layout
- Footer: centered "هل تحتاج إلى مساعدة؟ " + bold "تواصل معنا" (this "تواصل معنا" is NOT tappable — plain `Text`, not a button; a likely UX gap/dead affordance)

**Colors:** `AppColors.cream` background throughout. Primary card colors come from `EchoColors` (theme-inverting token set — cream-on-navy in light mode, navy-on-cream in dark mode; this is `theme.dart`'s documented deliberate exception to how every other navy/cream usage in the app behaves). Card radius `_kCardRadius = 24.0` — note this is a **local override**, not `AppSpacing.cardRadius` (20) — a real, confirmed deviation. Terracotta only used for: the "ابدأ الاستماع" CTA, the middle wave-bar, and (functionally) nothing else on this screen.

**States (all real, gated by `StudentProfile.current` / platform-fetched `enabledTools`):**
1. **Fail-open / not platform-linked** — every mode card shown (`_isModeEnabled` returns true unconditionally if `!profile.isPlatformLinked`).
2. **Gated** — once linked, a mode's card is hidden entirely unless its tool code (`DEAF_MODE`, `VISUAL_MODE`, `PHYSICAL_MODE`, `LEARNING_MODE`) is in `enabledTools`. Live-captured state (see screenshot) shows **all four modes enabled**.
3. **Last-session label states**: `_lastSessionLoaded == false` → empty string (brief flash); `null` (no transcript ever saved) → "لم تبدأ أي جلسة استماع بعد"; else → real relative time via `timeago`. Live-captured: "آخر جلسة: منذ 11 يوم".
4. **First-run AI consent** — on first ever open (`AppPrefs.getAiConsent() == null`), this screen triggers the Consent screen (Section 5) as a full-screen modal push before the student can interact further.
5. Entrance animation: whole screen fades/slides in once per screen mount (320ms).

**Navigation:** Reached from → Splash (session restored) or → Login (successful login). Leads to → Settings (gear icon), → Deaf Mode Transcription (primary card tap), → Visual Assistance Mode, → Physical Assistance Mode, → Learning Support Mode (whichever cards are enabled). Also triggers → Consent Screen as a one-time modal overlay.

**Screenshot:** `scratch_shots/01_after_splash.png` and `scratch_shots/16_home_recheck.png` — captured live with real enabled-tools gating (all 4 modes visible) and a real last-session timestamp.

## 5. Consent Screen (AI privacy consent)

**File:** `lib/pages/consent/consent_screen.dart`

Not in the route table at all — pushed via `Navigator.of(context).push(MaterialPageRoute(fullscreenDialog: true, builder: (_) => const ConsentScreen()))` from `showAiConsent()`, called in two places: (1) automatically, once, from Welcome Selection's `initState` post-frame callback if `AppPrefs.getAiConsent() == null`; (2) on-demand via `ensureAiConsent(context)` from any AI-invoking action across Deaf/Visual/Learning modes if consent hasn't been granted yet.

**Literal text — 100% hardcoded Arabic, no `.tr()`, no English variant exists for this screen at all:**
- `الخصوصية والموافقة` (title)
- `تستخدم بعض ميزات شادو خدمات خارجية (أطراف ثالثة) لتشغيل الذكاء الاصطناعي:`
- Bullet 1: `صوت المحاضرة يُرسل إلى خدمة Deepgram لتحويله إلى نص.`
- Bullet 2: `الصور ونصوص ملفات PDF تُرسل إلى خدمة Google Gemini لوصفها وتبسيطها.`
- Note 1: `قد يلتقط تسجيل الصوت صوت المُحاضِر، وهو أيضاً شخص معنيّ بحماية بياناته. استخدم الميزة بما يحترم خصوصيته.`
- Note 2: `لا تُرسل أي بيانات طبية أو سجلات إعاقة إلى هذه الخدمات، ولا يُرسل سوى ما تختاره أنت من صوت أو صور أو ملفات.`
- `إذا لم توافق، تبقى ميزات الذكاء الاصطناعي متوقفة ويمكنك تفعيلها لاحقاً.`
- `أوافق وأتابع` (accept button, appears twice — a11y label + visible text)
- `لا أوافق` (decline button, visible text; a11y label is the longer `لا أوافق، تبقى ميزات الذكاء الاصطناعي متوقفة`)

**Structure (top to bottom, RTL, `CrossAxisAlignment.end` throughout the scroll body):**
- 64×64 navy rounded icon tile with a privacy icon
- Title
- Intro paragraph
- 2 bullet points (terracotta dot + text)
- 2 note boxes (`AppColors.surface` bg, `AppColors.border`, `AppSpacing.cardRadius`)
- Closing disclaimer line
- Fixed bottom: full-width "أوافق وأتابع" button (navy fill) + "لا أوافق" button (outlined, `AppColors.border`)

**Colors:** `AppColors.cream` bg, standard `AppSpacing.cardRadius` (20) for icon tile and note boxes — no local overrides here, unlike most other screens.

**States:** `PopScope(canPop: false)` — the student **cannot dismiss this screen** without an explicit choice (no back button works). Two outcomes only: accept (returns `true`, persists `AppPrefs.setAiConsent(true)`) or decline (returns `false`, persists `false`). No loading/error state — purely local, synchronous.

**Navigation:** Reached from → Welcome Selection (automatic, first run) or → any AI-gated action in Deaf/Visual/Learning modes (on-demand, whenever consent hasn't been granted). Leads back to whichever screen invoked it (`Navigator.pop`), never navigates forward on its own.

**Screenshot:** Not captured — the demo account had already granted consent in an earlier session (confirmed no consent prompt appeared on relaunch), and forcing a fresh first-run state would require clearing app data (destructive to the already-logged-in demo session state used for the rest of this inventory). Documented from full source read only.

## Inconsistencies actually observed (concrete, cited)

1. **Real `AppBar` vs. custom header row is inconsistent across the app.** Settings (`settings_screen.dart:106`) and Saved Transcripts (`saved_transcripts_page.dart:212`) use a genuine Flutter `AppBar`. Every other screen with a header (Deaf Mode, Visual Mode, Learning Mode, Physical Mode, all 3 Voice Exam screens) hand-builds an equivalent-looking header from `Container`+`Row`+`Padding`+a manual 1px border `Container`. Visually near-identical but structurally two different implementations — a real duplication/consistency risk for a Figma component library.

2. **Card corner radius is not standardized** — at least 6 distinct values are used for what is visually "the primary card" pattern, each hardcoded per-screen rather than drawn from `AppSpacing.cardRadius` (20.0):
   - Home screen: `_kCardRadius = 24.0` / `_kEchoRadius = 24.0` (`welcome_selection_widget.dart:25-26`)
   - Deaf Mode: `_kPrimaryCardRadius = 26.0` / `_kEchoRadius = 26.0` (`deaf_mode_transcription_widget.dart:34-35`)
   - Visual Mode: `_kPrimaryCardRadius = 24.0` (`visual_assistance_mode_widget.dart:24`), but its inner camera frame uses `18.0` (`visual_assistance_mode_widget.dart:313`)
   - Learning Mode: `_kPrimaryCardRadius = 24.0` (`learning_support_mode_widget.dart:24`), but its font-size card uses `18.0` (`learning_support_mode_widget.dart:729`) and its secondary tool buttons use `16.0` (`learning_support_mode_widget.dart:578`)
   - Settings: radio-cards and sign-out row both use `18.0` (`settings_screen.dart:250, 203`), independently of the above
   - Login: text fields use `12.0` (`login_widget.dart:260,264,268`), submit button uses full pill `AppSpacing.pill` (999)
   - Voice Exam Confirm/Session action buttons: `16.0` (`voice_exam_confirm_widget.dart:115,133`; `voice_exam_session_widget.dart:566`)
   - Voice Exam List cards: `20.0` (matches `AppSpacing.cardRadius`, `voice_exam_list_widget.dart:208`)
   
   Only Consent Screen and Voice Exam List actually use the shared `AppSpacing.cardRadius` token as-is; every other "card" screen defines its own local override.

3. **Login, Consent, and Saved Transcripts have zero localization** — no `.tr()`, no `easy_localization` import, Arabic-only hardcoded strings, while every other screen in the app is fully bilingual (AR/EN) via `assets/translations/{ar,en}.json`. This means the app's own "لغة التطبيق" (App language) setting — which explicitly promises to "تُطبَّق فوراً — تغيّر لغة الواجهة" (applies immediately, changes the interface language) — silently does **not** apply to 3 real, reachable screens.

4. **`modes.physical.desc` translation string is stale relative to the actual Physical Mode screen.** ar.json/en.json still describe it as "تحكّم كامل بالصوت مع اتصال سريع بجهة الطوارئ" ("Full voice control with a quick-contact shortcut to an emergency contact"), but the current, simplified `physical_assistance_mode_widget.dart` has no voice-command mic, no "الأوامر المدعومة" list, and no emergency-contact button at all — confirmed by the file's own header comment describing the removal, and by the live screenshot showing only a single "اختبار صوتي" button.

5. **`AppColors.success` is used exactly once for a background fill** (the "مكتمل" status pill in Voice Exam List, `voice_exam_list_widget.dart:241`, `AppColors.success.withValues(alpha: 0.15)`), while every other screen only ever uses it for a small icon/checkmark accent (e.g. the finished-state check-circle in Voice Exam Session). A single-use background application of a status color is worth flagging — either intentional (this is genuinely the app's only "completed" list-item state) or an opportunity to define a proper status-pill component.

6. **Back-icon/back-affordance implementation is inconsistent.** Most screens use the shared `appBackIcon(context)` helper (`lib/a11y.dart`) inside a custom or `FlutterFlowIconButton`. Saved Transcripts relies on `AppBar`'s automatic default leading widget instead (no explicit `appBackIcon` call in `saved_transcripts_page.dart`) — meaning its back chevron's exact glyph/direction-handling is Flutter's platform default, not guaranteed pixel-identical to every other screen's hand-picked RTL-aware chevron.

7. **The settings icon in Deaf Mode Transcription's header does not open the Settings screen** — it opens a screen-local font-size `AlertDialog` (`_showSettingsDialog()`, `deaf_mode_transcription_widget.dart:305`), a completely different destination than the identical-looking gear icon on the Home screen (which does open the real Settings screen, `welcome_selection_widget.dart:227`). Same icon, same implicit affordance, two different behaviors — a real usability/consistency issue to flag for the redesign, not just a visual one.

8. **The "echo card" and "wave bars" visual patterns are copy-pasted per screen, not shared components** (see Reusable Widgets section above) — 4 near-identical echo-card implementations and 2 near-identical wave-bar implementations exist as separate private classes/methods, each with slightly different constants (radius values, bar counts, bar heights). A prime candidate for consolidation into shared components in the Figma library and, eventually, in code.

9. **Splash Screen is the only screen with a full navy-page background**; every other screen uses `AppColors.cream`. This is very likely intentional (brand moment on launch) but is a real, singular deviation worth calling out explicitly since the rest of the design system is cream-first.
